# Этап 4.1. CI, тесты миграций Room, эталонные тесты детерминизма

Перед работой прочитай `AGENTS.md` и `tasksandreports/README.md`. Работа идёт прямо в `main`. Без попутных рефакторингов. Избегай избыточных тестов (правило `AGENTS.md`): нужны тесты, которые ловят реальные регрессии, а не «на всякий случай».

Этап 4 разбит на две задачи. Эта (4.1) ставит страховочную сетку, следующая (4.2) убирает дублирование правил и добавляет мелкие исправления.

## 1. CI на GitHub Actions

### Как сейчас

CI нет совсем: нет `.github/workflows` и вообще никакой конфигурации CI.

### Что сделать

Workflow `.github/workflows/ci.yml` на `push` в `main` и на `pull_request`, ubuntu-latest, JDK 17, кэш Gradle (`gradle/actions/setup-gradle`), Android SDK (существующий action или sdkmanager; уровень API — как в `app/build.gradle.kts`).

Задачи — параллельными job'ами или по шагам, на твоё усмотрение. Должно уложиться в разумное время, ориентир ≤ 20–25 минут:

1. **ktlint всех модулей:** `ktlintCheck`.
2. **Тесты `:puzzle-core` на JVM:** `jvmTest`. Если на раннере работают headless-тесты JS/Wasm (на GitHub Chrome есть, в отличие от облака), добавь `:puzzle-core:allTests`. Если не заработают, оставь только `jvmTest` и опиши почему.
3. **Web-тесты `:web-app`:** `jsBrowserTest` на раннере, а если не выйдет — тот же Node-путь, что в `.claude/scripts/web-tests-node.sh`.
4. **`:app` без RuStore:** `-Plogica.withoutRustore=true :app:testDebugUnitTest :app:lintRelease`. Раннеры GitHub, скорее всего, тоже получат 404 от репозитория RuStore. Если репозиторий доступен, это не страшно: свойство просто исключает SDK.
5. **Сборка Wasm-дистрибутива:** `:web-app:wasmJsBrowserDistribution` или задача, которой собирается продакшн-дистрибутив. Если она слишком тяжёлая для раннера (линковке нужно 4 ГБ, см. `gradle.properties`), ограничься компиляцией `compileKotlinWasmJs` и опиши это.

Требования:

- Секретов и приватных настроек в workflow нет: релизных рекламных юнитов, ID RuStore и подписи. Debug использует демо-юниты, как сейчас.
- **Проверка запуска.** Если у тебя есть доступ к GitHub Actions через MCP-инструменты GitHub, запусти workflow пушем и приложи к отчёту итог прогона: ссылку или статус job'ов. Если доступа нет, так и напиши. Тогда владелец посмотрит первый прогон сам.
- Если в CI падает что-то, что уже было сломано до этапа, не чини это здесь. Пометь в отчёте, а при необходимости временно исключи с комментарием и ссылкой на задачу.

## 2. Тесты миграций Room

### Как сейчас

В `app/schemas` экспортированы схемы 1–10, миграции `MIGRATION_*` объявлены в `LogicaDatabase.kt`, но ни одного теста миграций нет. Это противоречит правилу «migrations preserve existing saves».

### Что сделать

- **Тесты миграций на JVM, без устройства.** Room здесь — `androidx.room3` 3.0.1 с bundled SQLite. Используй подходящий для JVM `MigrationTestHelper` из room3-testing, если он есть для этой версии, со схемами из `app/schemas`. Если нет, возьми `BundledSQLiteDriver`, создай базу по SQL из JSON-схемы версии N, заполни её и прогони миграции.
- **Что должны покрывать тесты:**
  - полная цепочка 1 → 10 на базе с данными: результаты, Daily, экономика, прогресс, где они уже существуют в исходной версии. Данные сохраняются, новые колонки получают значения из `AGENTS.md`:
    - `outcome = SOLVED` в 4→5;
    - кошелёк 0 гемов и 5 жизней в 5→6;
    - стартовые подсказки в 8→9;
    - `stars = NULL` в 9→10;
  - каждая миграция по отдельности: после неё схема совпадает с экспортированной (`validate`, если хелпер это умеет);
  - открытие базы последней версии с полным набором миграций без `fallbackToDestructiveMigration`.
- **Зависимость.** room3-testing, если понадобится, добавь только в `testImplementation`, через `libs.versions.toml`.
- **Найденные расхождения.** Если тест найдёт ошибку в существующей миграции, не исправляй миграцию молча. Опиши в отчёте, что именно не так, и предложи исправление: это решение уровня владельца, ведь у игроков уже есть базы.

## 3. Эталонные (golden) тесты детерминизма

### Как сейчас

`CrossPlatformDeterminismTest` проверяет только `PuzzleRandom` и начало 2048. Большинство тестов ядра идут только на JVM. Замороженные паки хранят лишь seed'ы, поэтому, если генератор начнёт выдавать на JS/Wasm другой результат, Android и Web покажут разные головоломки, и никто этого не заметит.

### Что сделать

- **Тесты в `puzzle-core/src/commonTest`**, чтобы они шли на всех целях. Сравнивать с жёстко записанным в тест эталоном: компактным отпечатком, например строкой из клеток или хешем, который считается в `commonMain` без платформенных API. Для каждой игры — один-два фиксированных seed'а на одной сложности:
  - Balance V1: givens и решение;
  - Crowns V1: регионы и решение;
  - Sudoku: выбор записи Dataset V1 по селектору, если он работает без загрузки ресурсов в `commonTest`; иначе пропусти и объясни;
  - Word V2: ответ для seed'а, если лексикон доступен в `commonTest`; иначе пропусти и объясни;
  - 2048: первые N спавнов после фиксированной последовательности ходов;
  - Nonogram V1 и V2: картинка;
  - Block Sudoku V1: первые 3 раздачи для seed'а.
- **Откуда берётся эталон.** Его даёт текущий JVM-результат. Если на JS или Wasm результат отличается, это находка уровня P0: опиши её в отчёте и не подгоняй эталон.
- **Где запускать.** В облачной среде браузерные тесты JS/Wasm не запускаются (нет Karma). Проверь `jvmTest`, а JS и Wasm проверит CI из пункта 1. Если в CI JS/Wasm тоже не работают, напиши это явно.

## 4. Мелкое исправление из этапа 3

`RoomDailyChallengeRepository`: командный цикл теперь при любой `CancellationException` из обработки команды отменяет ответ и завершается. Если такое исключение придёт не из-за отмены самого scope (например, отменилась внутренняя работа), цикл умрёт навсегда, и все чтения Daily в сессии зависнут.

Что сделать:

- **Когда пробрасывать отмену.** Только если отменён сам scope цикла (`!isActive` / `coroutineContext.ensureActive()`).
- **Иначе** — завершить ответ этой команды ошибкой и продолжить цикл.
- **Тест:** команда, внутри которой бросается `CancellationException` при живом scope, не останавливает цикл, и следующая команда выполняется.

## Проверка перед пушем

