## Что сделать

### 1. Ядро и данные

- **`NonogramGeneratorV3`** — картинка из замороженной библиотеки своей сложности по индексу.
  - Библиотека — ресурс `nonogram/v3/<difficulty>.txt`, на вебе грузится лениво по образцу словарей Word, а не данными Kotlin.
  - Порядок и содержимое замораживаются навсегда, как у `NonogramPictureSetV1`.
- **Перед заморозкой — одна мера усилия.** Пересчитай деление картинок 15×15 на Сложно/Эксперт через Kotlin `NonogramLineSolver.solveWithEffort`, а не через Python-меру. Числа по сложностям запиши в отчёт. Если граница сдвинет число картинок ниже 150 на сложность, опиши и всё равно держись правила «Сложно ≤ 4 прохода, Эксперт ≥ 5», как у V4.
- **Пак `CatalogLevelPackVersion(2)` — только для Nonogram:**
  - нечётный слот `s` — картинка `order[((s + 1) / 2 − 1) mod N]` (V3), где `order` — один перемешанный (проектным RNG с фиксированным сидом) цикл библиотеки;
  - чётный слот `s = 2k` — k-й принятый сид V4.
- **Версия генератора по слоту** выводится в `CatalogLevelPacks`/`BinaryCatalogLevelPack` для `(NONOGRAM, V2)`. `PuzzleId` и `game_results.generator_version` говорят V3 или V4 честно.
- **Заморозка** — `buildCatalogLevelPacks` пишет `levels/v2/nonogram/<difficulty>.lvp` только если их нет, контрольные суммы добавляются. Все бакеты V1 проверяются как есть.

### 2. Переход прогресса (обе платформы)

- **Активная версия пака для Nonogram — V2.** Сделай её функцией `puzzleType → версия`, а не одним полем репозитория. Остальные игры остаются на V1.
- **Строка/бакет V2** при первом обращении создаётся с текущим уровнем = текущий V1. Room-схема не меняется: это новая строка; на вебе — новый ключ бакета в том же снимке.
- **Текущий уровень Nonogram = `max(V1, V2)`.** Запись в V2 не опускает его ниже V1, потому что старое устройство может двигать V1.
- **Чётность — по абсолютному номеру уровня:** нечётный — картинка, чётный — симметрия.

### 3. Галерея, повторы, звёзды, рейтинг

- **Галерея.** Уровни `1…(V1 − 1)` строятся из пака V1 генератором V1, дальше — из пака V2. Граница — строка V1, ничего нового не хранится. Android `GameSheets` (галерея Нонограммы), Web `WebNonogramController.galleryPicture` и `WebGameFlows`.
- **Повтор из галереи** открывает уровень в паке его диапазона (`CatalogLevelId` несёт версию). Проверка завершения «текущий или пройденный» идёт по бакету этой версии.
- **Звёзды** — по бакету версии (уже так). Проверь `levelRecords()` на вебе и `bestLevelStars` на Android: сумма звёзд в профиле и на карточках сложности не должна терять звёзды V1.
- **Рейтинг Nonogram** — `max(V1, V2) − 1` на сложность, без суммы бакетов.
- **Карточка результата** (10.5) показывает картинку V3 и узор V4 так же, как остальные.
- **Daily не меняется**: V2 над 60 картинками.

### 4. Тесты (обязательно)

- **Пак:** `resolve` нечётного и чётного слота, версия на определении, детерминизм. Хеши V1 не изменились, новые записаны.
- **Переход на Android и вебе:**
  - игрок на V1-уровне 37 → следующий уровень 37 из пака V2 (нечётный → картинка);
  - решение двигает V2;
  - V1 больше не растёт;
  - `max` при росте V1 со «старого устройства».
- **Галерея:** уровни 1–36 из V1, 37+ из V2.
- **Повтор уровня 10 (V1) и уровня 38 (V2):** правильный пак, звёзды только повышаются.
- **Рейтинг:** нет двойного счёта.
- **Облако веба:** слияние снимков с бакетами V1 и V2 с двух устройств, одно из них «старое», без бакета V2.
- **Golden:** V3 (индекс → картинка) и V4 — на всех целях.
