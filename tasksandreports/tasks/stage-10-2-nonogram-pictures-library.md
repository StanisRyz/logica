# Этап 10.2. Nonogram: настоящие картинки в уровнях — библиотека, превью и проект перехода (без изменений в игре)

Перед работой прочитай `AGENTS.md` и `tasksandreports/README.md`. Работа идёт прямо в `main`.

## Решение владельца

Уровни Catalog в Nonogram должны быть **настоящими рисунками**, а не случайной симметрией (сейчас Generator V1). В Daily настоящие рисунки уже есть: `NonogramGeneratorV2` над замороженным набором из 60 картинок 10×10 (`NonogramPictureSetV1`).

Паки уровней замораживаются навсегда. Поэтому этот этап только готовит:
- библиотеку картинок;
- превью для владельца;
- проект перехода.

**Игра не меняется, паки не пишутся.** Встраивание — отдельной задачей после одобрения владельца.

## Что сделать

### 1. Библиотека картинок

- **Размеры по сложностям.** Предложи свои. Ориентир: Easy 5×5, Medium 10×10, Hard 15×15, Expert 15×15 сложнее или 20×20. Учти, что поле должно помещаться на телефоне 360 dp без прокрутки игры (есть `ZoomableBoard`), и обоснуй выбор.
- **Сколько картинок.** На каждую сложность столько, чтобы игрок не видел повторов долго: ориентир — от 150 картинок на размер. Больших размеров можно меньше, если не набирается. После конца набора бакет повторяется детерминированно — это разрешено правилом `AGENTS.md` о бакетах с малым числом разного содержимого.
- **Откуда брать картинки — сравни два пути и выбери (или смешай):**
  - **нарисованные вручную ASCII-картинки**, как в `NonogramPictureSetV1`: предметы, животные, еда, транспорт, символы;
  - **растеризация открытых наборов иконок** с подходящей лицензией (Material Symbols — Apache-2.0, Tabler — MIT, Lucide — ISC и т. п.) в сетку нужного размера с порогом и последующим отбором.

  Для растеризации — офлайн-скрипт разработчика в `tools/nonogram/`, исходники и лицензии — в `datasets/nonogram/`. Никакой загрузки во время игры.
- **Фильтры, обязательные для каждой картинки:**
  - решается только логикой строк (`NonogramLineSolver`), одно решение, без догадок — как у V1 и V2;
  - не пустая и не почти сплошная;
  - нет дубликатов, в том числе зеркальных.
- **Сложность.** Внутри размера оцени её по шагам решателя: сколько проходов, есть ли строки, которые открываются только в связке. Предложи, как развести Hard и Expert, если у них один размер.
- **Название.** У каждой картинки ключ-название на английском, как в V1 (`KEYS`). В отчёте предложи, показывать ли название после решения: «Это — кошка». Это отдельное решение владельца.

### 2. Превью для владельца

Сгенерируй `tasksandreports/reports/img/stage-10-2/` — по одному листу PNG на сложность: сетка всех картинок с номером и ключом. Это главное, по чему владелец будет решать. Лёгкий формат, не больше ~2 МБ на лист.

### 3. Проект перехода (документ, без кода)

В отчёте опиши, как перейти на новые картинки, **не сломав**:
- заморозку паков;
- прогресс игроков;
- галерею;
- звёзды;
- рейтинг;
- облачные сохранения веба.

Решение архитектора-основа, проверь его по коду и уточни:

- **Новая версия пака** `CatalogLevelPackVersion.V2` — только для Nonogram, с новым генератором `NonogramGeneratorV3` над новой библиотекой. Старые бакеты V1 остаются и проверяются как есть.
- **Нумерация уровней продолжается.**
  - Строка прогресса V2 при первом обращении начинается с текущего уровня V1. На Android это новая строка в существующей таблице, а не новая колонка; на вебе — новый ключ бакета в том же снимке.
  - Строка V1 после этого больше не растёт.
  - Уровни 1…(текущий V1 − 1) — история V1, дальше — V2.
- **Галерея.** Уровни 1…(V1 текущий − 1) строятся из пака V1, дальше — из V2. Граница выводится из замершей строки V1, ничего нового не хранится.
- **Звёзды и повторы.** Проверь, что звёзды Android (`game_results` хранит версию пака) и веба (`logica_catalog_stars_v1` — какой ключ?) не путают V1 и V2 с одинаковым номером уровня. Повтор старого уровня из галереи открывает его в паке V1.
- **Рейтинг** (`PuzzleRating`): текущий уровень активной версии − 1, без двойного счёта.
- **Облако веба.** Слияние каталога монотонное по бакету `тип + сложность + версия пака`. Проверь, что устройство со старой версией игры и устройство с новой не испортят друг другу прогресс.
- **Daily не меняется**: V2 над 60 картинками.

Для каждого пункта укажи файлы и функции, которые придётся менять, и риски. Если найдёшь путь проще с тем же результатом, предложи его.

## Чего не делать

- Не писать и не менять паки, генераторы V1/V2, Room, форматы сохранений.
- Не встраивать V3 в игру.

## Проверка

Если добавлен код в `:puzzle-core` (например, `NonogramGeneratorV3` и библиотека как данные с тестами решаемости), запусти:

```
./gradlew ktlintCheck :puzzle-core:jvmTest
```

Код не должен подключаться к игре. После пуша — зелёный CI.
