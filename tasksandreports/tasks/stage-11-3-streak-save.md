# Этап 11.3. Сохранение серии Daily

Перед работой прочитай `AGENTS.md` и `tasksandreports/README.md`. Работа идёт прямо в `main`.

Решение владельца: игрок может спасти серию Daily, если пропустил один день.

## Правило (решение архитектора; числа временные, владелец может поменять)

- **Когда предлагается.** Сегодня D. Вчера (D−1) не засчитано в серию, а позавчера (D−2) засчитано, и серия, закончившаяся на D−2, не короче **3 дней**. Тогда весь день D можно восстановить день D−1.
  - Восстанавливается только один пропущенный день, только вчерашний. На D+1 предложение пропадает.
  - **Не чаще одного восстановления за 7 дней:** между датами двух восстановлений не меньше 7 дней.
- **Цена:** **15 гемов** или **1 rewarded-реклама**. Числа — в `EconomyPolicy` (`STREAK_RESTORE_GEMS`, `STREAK_RESTORE_MIN_STREAK = 3`, `STREAK_RESTORE_COOLDOWN_DAYS = 7`); `EconomyParityTest` / `WebEconomyParityTest` их видят.
- **Что даёт.** Восстановленная дата считается засчитанной **только для серии** (текущая и лучшая, достижения о сериях).
  - Daily-счётчик «полных Daily» не растёт.
  - В календаре профиля день помечен отдельно: «серия сохранена». Знак и текст, не только цвет.
- **Правило серии в ядре.** `DailyStreakCalculator.calculate` получает восстановленные даты как обычные засчитанные. Хосты передают объединение.
  - Отдельная чистая функция в `:puzzle-core` `daily/` решает, доступно ли восстановление: `(today, qualifiedDates, restoredDates) → дата D−1 или null`. Тесты: граница 3 дня, кулдаун 7 дней, сегодня уже засчитан (тоже можно — серия всё равно прервана вчера), D−1 уже восстановлен.

## Хранение (разрешено этим заданием)

- **Android.** Без изменения Room-схемы: строка `economy_events` с ключом `streak_restore:<date>`.
  - Гемы — `gem_delta = −15`. Реклама — 0 гемов, источник `rewarded`.
  - Восстановленные даты выводятся из этих строк.
  - Повторный запрос с той же датой — no-op, как у прочих строк журнала.
  - Реклама — через `RewardedLifeController` / тот же путь, что `+1 гем`, с action id до показа.
- **Веб.** Player-scoped запись наград `LGDR` получает новую версию с полем восстановленных дат. Старые версии читаются.
  - Слияние — объединение множеств. Синхронизация — через раздел unified save `rewards`, как сейчас.
  - Порядок: сначала дата закрепляется в записи надёжно, потом списываются гемы. Худший случай при сбое — игрок получил восстановление бесплатно, а не потерял гемы. Повтор с той же датой гемы не списывает.
  - Реклама — своё rewarded-размещение `streakRestore` на общем кулдауне, с проверкой Player-контекста до выдачи, как у `+1 жизнь`.
- Восстановление — не результат игры: ни `GameResult`, ни статистика, ни квесты, ни рейтинг.

## Интерфейс (оба хоста, общая презентация в `:shared-ui`)

- **Game Hub, раздел Daily.** Пока восстановление доступно — компактная строка «Серия N дней прервалась. Спасти?» с двумя кнопками: «15 [гем]» (`GemPriceButton`) и «Смотреть рекламу» с явной надписью «за рекламу» (требование Яндекса 4.5).
  - Нехватка гемов говорит, чего не хватает.
  - После восстановления строка исчезает, серия обновляется сразу.
- **Профиль, календарь** — отметка восстановленного дня и её описание.
- Тексты на трёх языках, числа через `<plurals>`.

## Тесты

- Ядро: функция доступности и серия с восстановленными датами.
- Android: строка журнала идемпотентна; серия и достижения видят восстановленную дату; Daily-счётчик не меняется.
- Веб: кодек новой версии записи и чтение старой; слияние объединением; повтор не списывает дважды; смена игрока во время рекламы ничего не даёт.
