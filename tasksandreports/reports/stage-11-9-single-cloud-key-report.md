# Этап 11.9. В облако пишется только один ключ

## 1. SHA коммитов

- `d174100` — старые ключи только для чтения, фабрика `YandexCloudGateways`, тест, подставной SDK с заменой в `check_sounds.mjs`, `AGENTS.md`.
- Отчёт и уточнение комментария `WebCloudWritePacer` — следующим коммитом.

## 2. Что сделано

- **Один записываемый ключ.**
  - Новая фабрика `YandexCloudGateways` (`YandexPlayerGateways.kt`) строит все четыре облачных шлюза Яндекса: единое сохранение `logica_unified_save_v1` с пейсером и три старых ключа (`logica_state_v1`, `logica_statistics_v1`, `logica_daily_v1`) только для чтения.
  - У `YandexCloudSaveGateway` новый параметр `writable`. При `false` вызов `write` сразу возвращает `CloudSaveWriteResult.Unsupported` и SDK не трогает.
  - `Main.kt` берёт шлюзы из фабрики.
  - Любой `setData` теперь несёт ровно один ключ, и результат одинаков, сливает ли Яндекс ключи или заменяет все данные игрока.
- **Чтение старых ключей при восстановлении не менялось.** Слияние старых облачных данных с локальными работает как раньше.
- **Контроллер сессии не менялся.**
  - Старая синхронизация по-прежнему вызывает `write` у старых шлюзов. Ответ `Unsupported` она уже умела обрабатывать: внутренний статус становится `ERROR`, привязка игрока продолжается.
  - Эти статусы нигде в интерфейсе не читаются (проверено поиском).
  - Пока единая запись не установлена, облако не получает ничего; восстановление повторяется (~2/8/30 с и при следующем изменении), как и было.
- **Других `setData` нет.** Единственный вызов SDK — `YandexGamesBridge.writePlayerData`, и через него ходят только облачные шлюзы. Платежи, турнир и настройки хранятся в `localStorage` и в единой записи.

## 3. Тесты

Новый `WebSingleCloudKeyTest`, 2 теста. Подставной мост в нём при каждом `setData` **заменяет** все данные игрока.

- **`legacyKeysAreReadOnlyAndNeverReachTheSdk`.** Запись в три старых шлюза отвечает `Unsupported`. До моста доходит только единый ключ.
- **`aFailedUnifiedReadOnAnotherDeviceNeverLosesTheFirstDevicesProgress`** — сценарий из задачи, на двух устройствах с полным контроллером сессии и планировщиком:
  1. Устройство A (уровень 12) устанавливает единую запись.
  2. У устройства B первое чтение единой записи падает, а его старая синхронизация статистики хочет записать.
  3. Единая запись A остаётся нетронутой.
  4. После восстановления чтения B получает уровень 12 и сам устанавливает облако.
  5. Мост видел только `logica_unified_save_v1`. Этот путь покрывает установление, старую синхронизацию до установления, повторы и `flushNow`.
- **Проверка теста на старом поведении.** Если временно сделать старые ключи записываемыми, оба теста падают: «Expected <Unsupported>, actual <Saved>» и «Expected <12>, actual <null>» — единая запись A стёрта. Исходный код восстановлен.

Существующие тесты не менялись: шлюз по умолчанию остаётся записываемым, а тесты таймаутов используют его напрямую.

**Подставной SDK.**
- В `tools/web/check_sounds.mjs` подставной `setData` теперь заменяет все данные. Добавлена проверка «облако получает только единый ключ». Режим Яндекса — 20/20.
  - Оговорка: на свежем игроке старая версия тоже проходит эту проверку (19/20 — падает только проверка blur из 11.8), потому что старой синхронизации нечего писать. Сценарий с данными покрывает модульный тест выше.
- Подставной SDK из 11.5 (вне репозитория) тоже переведён на замену. Прогон страницы турнира с засеянной статистикой: консоль без ошибок.
  - Сборка 11.8 записала `logica_statistics_v1` и `logica_unified_save_v1`, причём первую запись вторая стёрла.
  - Сборка 11.9 записала только `logica_unified_save_v1`.

## 5. Отклонения и вопросы

- **Старая синхронизация ещё вызывает `write`.** Вызов сразу отвечает `Unsupported`, без SDK; во внутреннем статусе это `ERROR`, игроку не видно. Удалять эти ветки из контроллера не стал: задача просит no-op в шлюзе, а контроллер без изменений меньше рискует.
- **Старые ключи в облаке не стираются.** Они просто перестают обновляться. Если Яндекс заменяет данные целиком, первая же единая запись их уберёт; если сливает — они останутся только для чтения при миграции.
