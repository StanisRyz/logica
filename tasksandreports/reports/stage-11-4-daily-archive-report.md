## 2. Что сделано

### Правило (ядро, `:puzzle-core` `daily/`)

- **`DailyArchive.dates(today, days)`** — дни архива, новые сверху: от вчера до `days` дней назад; сегодня в архив не входит.
- **`DailyArchive.contains(today, date, days)`** — входит ли день в окно.
- **`DailyArchive.definitionFor(date, persistedPolicy)`** — состав дня:
  - по политике сохранённого прогона: старый V7 остаётся V7 с русским Word;
  - без прогона — `NEW_RUN_VERSION` (V8).

  Определения детерминированы по дате, случайного сида нет.
- **`dailyDateOfEpochDay(epochDay)`** — новая `expect`-функция, обратная `toDailyEpochDay`:
  - JVM и Android: `LocalDate.ofEpochDay`;
  - веб: свой проверенный алгоритм civil-from-days.

  Нужна потому, что в общем коде нельзя построить `DailyDate`.
- **Числа** в `EconomyPolicy`: `DAILY_ARCHIVE_DAYS = 30`, `DAILY_ARCHIVE_UNLOCK_GEMS = 5`.

### Открытие дня

| Как | Android | Веб |
|---|---|---|
| За гемы | строка `daily_archive:<эпоха-день>`, `gem_delta = −5`, источник `gems`; баланс перечитывается в той же транзакции | день сначала надёжно пишется в запись наград, потом `spendGems(5)` |
| За рекламу | та же строка с 0 гемов, источник `rewarded`; через `RewardedLifeController.showDailyArchive`, action id до показа, в журнал пишет только колбэк награды | размещение `dailyArchive` (общий кулдаун, проверка Player-контекста до выдачи); награда — запись дня |
| Бесплатно (день начат в свой день) | строка с источником `free` пишется при первом запуске задачи | день открыт уже потому, что в истории Daily есть его запись; писать нечего |
| Повтор | строка — граница дубля, ничего не списывается | `claimDailyArchive` вернёт `false`, гемы не списываются |

### Засчитывание

- **Игра — обычный Daily за ту дату:**
  - жизни: 0 жизней блокирует запуск, `FAILED` и выход с прогрессом стоят жизнь;
  - второй шанс, правила 2048 Daily, интерстишиалы при выходе;
  - статистика записывает попытку.
- **Календарь и «полные Daily».** Решения архива заполняют день. Полный день считается в «полные Daily».
- **Серия архив не засчитывает:**
  - **Android** (`DailyStreakQualification.qualifiedDates(..., archiveUnlockedAt)`):
    - результат даты D засчитывает серию, только если сохранён раньше `created_at` строки `daily_archive:<D>`;
    - завершённый прогон засчитывается, только если его последнее решение было раньше открытия. Прогон завершается своим последним решённым результатом, поэтому время берётся из результатов, без изменения схемы и DAO прогонов;
    - даты без строки — все даты до архива — считаются как раньше.
  - **Веб.** Новая маска `onTimeSolvedMask` («решено в свой день»):
    - серия читает её (V5+: любая задача; V1–V4: все задачи в свой день);
    - полнота дня читает `solvedMask`, как раньше;
    - архивная попытка (`WebDailyAttempt.archive`) пишет решение только в `solvedMask`.
- **Квесты:**
  - квест «реши задачи дня» считает только сегодняшний Daily. На Android — по `challengeDate` результата; на вебе это уже было так: он читает запись сегодняшней даты;
  - квесты «сыграй / реши в игре …» считают архивные попытки как любые.
- **Шеринг** — только сегодняшний Daily, как был.

### Хранение на вебе

- **Снимок Daily, schema 2:**
  - девятый байт на запись — `onTimeSolvedMask`;
  - schema 1 читается, и маска в нём равна `solvedMask`;
  - пока все решения сделаны в свой день, снимок пишется как schema 1 — так старые сборки продолжают его читать. Тот же приём, что у статистики (schema 2 только с архивом);
  - слияние — побитовое ИЛИ.
- **Запись наград `LGDR4`.** Новое поле — открытые дни, слияние объединением. `LGDR3`, `LGDR2`, `LGDR1` читаются. Синхронизация — через раздел unified save `rewards`, как и раньше.
- **Запуск задачи** — `WebDailyGameplayCoordinator.start(puzzleType, archiveDate)`:
  - день вне окна не стартует;
  - токены и смена игрока работают как у сегодняшнего Daily.

### Интерфейс (общая презентация, `:shared-ui`)

- **Вход:**
  - кнопка «Архив» с иконкой истории внизу раздела Daily на Game Hub (`DailyHubSection(onOpenArchive)`);
  - тап по прошлому дню текущего месяца в календаре профиля (`DailyCalendarMonth.openableDays`; озвучка «Открыть в архиве»). Все прошлые дни месяца в пределах 30 дней.
- **`DailyArchiveList`:**
  - «Задачи дня за последние 30 дней»;
  - строки новыми сверху: значок (замок / играть / галочка), дата от хоста, `k / n`.
- **`DailyArchiveDayContent`:**
  - те же `DailyEntryCard`, что в разделе Daily, с датой в заголовке;
  - у закрытого дня — карточка «Откройте этот день» с пояснением, что серию архив не заполняет;
  - две кнопки: «5 [гем]» (`GemPriceButton`) и «Открыть за рекламу»;
  - нехватка гемов говорит, сколько не хватает.
- **Карточка результата архивной задачи** (`LocalDailyResultDateLabel`):
  - заголовок «Задача дня за 3 октября не пройдена / решена»;
  - выход — «К архиву»: игра возвращает на страницу этого дня, на Android и на вебе.
- **Широкое окно на вебе** (ландшафт ≥ 720 dp) — читаемая ширина 720 dp. На Android при ширине ≥ 720 dp тоже.
- **Тексты** на трёх языках; числа через `<plurals>`.
- `StreakRestoreAdState` переименован в `DailyRewardedAdState`: теперь им пользуются и спасение серии, и архив.

## 5. Отклонения и вопросы

- **Бесплатное открытие на Android всё равно пишет строку** (`free`, 0 гемов), при первом запуске задачи. Без строки решение такого дня в архиве засчитало бы серию задним числом: граница «до открытия» исчезла бы. На вебе строка не нужна — границу держит `onTimeSolvedMask`.
- **Верхняя панель архивной игры** по-прежнему говорит «К играм», хотя назад ведёт в архив. Кнопка карточки результата уже говорит «К архиву». Панель — общий `WebTopBar` / Android-заголовок игр; не трогал, чтобы не менять все игровые экраны.
- **Android вживую не проверен** (нет устройства). Экраны используют ту же общую презентацию; журнал и серия покрыты `DailyArchiveTest`, сборка и `lintRelease` проходят.
- **Реклама в автономной сборке** недоступна (нет SDK), поэтому открытие за рекламу на скриншотах не показано. Выдачу проверяют тесты: на вебе — размещение без награды с проверкой контекста, на Android — общий путь `RewardedLifeReward`.
- **Турецкий заголовок** «3 Ekim günün bulmacası çözülemedi» грамматически допустим, но носитель, вероятно, сказал бы «3 Ekim'in bulmacası». Строку легко поправить.

### Вопросы владельцу

Новых нет. Числа временные (30 дней, 5 гемов) и меняются в `EconomyPolicy` — `DAILY_ARCHIVE_*`.
