# Задачи и отчёты

Рабочий обмен между архитектором (ставит задачи и проверяет) и исполнителем (делает).

- `PLAN.md` — этапы работ и открытые решения владельца.
- `tasks/` — задачи. Пишет только архитектор.
- `reports/` — отчёты. Пишет только исполнитель.

## Имена файлов

- Задача этапа: `tasks/stage-NN-<кратко>.md`, например `tasks/stage-01-web-cloud-save-integrity.md`.
- Доработка по итогам проверки: `tasks/stage-NNa-<кратко>.md`, затем `NNb` и так далее.
- Отчёт называется так же, как задача, с суффиксом `-report`, например `reports/stage-01-web-cloud-save-integrity-report.md`.

## Ветка

Вся работа идёт прямо в `main`, отдельные ветки не нужны.

1. Архитектор коммитит задачу в `tasks/` и пушит в `main`.
2. Исполнитель делает `git checkout main && git pull origin main` и читает задачу.
3. Исполнитель выполняет работу, коммитит код и отчёт в `reports/`, затем делает `git pull --rebase origin main` и `git push origin main`.
4. Архитектор делает pull, проверяет дифф и прогоняет тесты, затем ставит следующую задачу или пишет доработку.

Работа идёт строго по очереди, поэтому конфликтов нет.

## Формат отчёта

1. SHA коммитов.
2. Что сделано, по пунктам задачи: файлы и ключевые решения.
3. Новые и изменённые тесты. Каждая правка существующего теста с объяснением, почему она нужна.
4. Команды проверки и их итог: сколько тестов прошло, `BUILD SUCCESSFUL` или `BUILD FAILED`.
5. Отклонения от задачи и их причины. Найденные, но не исправленные проблемы. Вопросы.
