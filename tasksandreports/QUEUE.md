# Очередь задач для автономной работы

Этот файл пишет только архитектор. Исполнитель его не правит.

## Как брать задачу

1. `git pull origin main`, перечитай этот файл.
2. Возьми **первую** задачу из списка ниже, у которой ещё нет отчёта в `reports/`. Отчёт называется как задача, с суффиксом `-report.md`.
3. Выполни её, закоммить код и отчёт, `git pull --rebase origin main`, `git push origin main`.
4. Сразу переходи к пункту 1. Подтверждения владельца или архитектора между задачами не жди.

Архитектор проверяет отчёты по ходу работы. Если найдёт проблему, он **вставит доработку (`stage-NNa`) выше по списку**. Поэтому перечитывай этот файл после каждой задачи: доработка идёт раньше следующей новой задачи.

## Правила долгой работы

- **Можно работать без остановки** (8 часов и больше), пока очередь не кончится.
- **CI.** Не жди CI после пуша, сразу бери следующую задачу. Но **перед следующим пушем** проверь CI своего прошлого пуша (GitHub MCP `actions_list`, owner `StanisRyz`, repo `logica`). Если он красный из-за тебя, сначала чини, потом пушь остальное. В отчёт — ссылка на зелёный прогон. Если отчёт уже запушен, допиши ссылку в следующем коммите.
- **Если задача упирается в решение владельца,** выбери самый консервативный и легко обратимый вариант. Опиши его в отчёте в разделе «Вопросы владельцу» и иди дальше.
- **Если пункт задачи невыполним** (инструмента нет, окружение не даёт), пропусти этот пункт, опиши причину и продолжай остальные пункты.
- **Если задача целиком заблокирована,** напиши короткий отчёт с причиной и переходи к следующей задаче.
- **Никогда без прямого указания в задаче:**
  - не менять Room-схему, форматы сохранений, ключи хранилищ, замороженные паки, детерминизм генераторов, числа экономики и правила рекламы;
  - не делать `force-push`, не переписывать историю, не трогать чужие ветки;
  - не отключать и не пропускать тесты;
  - не создавать PR.
- **Контекст.** Держи отчёты короткими, но полными по формату `README.md`. Если контекст сжимается, перечитай этот файл, `README.md` и текущую задачу.
- **Конец очереди.** Когда задач без отчёта не осталось, напиши `reports/queue-summary-report.md`: что сделано по каждой задаче (одной строкой со ссылкой на отчёт), что не сделано, все вопросы владельцу одним списком. Затем остановись.
